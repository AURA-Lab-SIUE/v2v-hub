How to run a code chunk

Look at the gray box below. At its top left corner there is a small Run Cell link, or a ▷ triangle. Click it.

If you do not see one, click anywhere inside the gray box and press Ctrl+Enter (Windows) or Cmd+Enter (Mac). That sends the line your cursor is on to R.

The first time you do this, VS Code may take twenty or thirty seconds to wake R up, and a new panel will open at the bottom of the screen. That panel is the R console: it is where R answers you. Slowness the first time is normal and is not a sign that anything is wrong.

Step 1: Is R alive?

This chunk asks R to say which version of itself it is running. It changes nothing. It is a pulse check.

R.version.string

What you should see: a line of text starting with "R version 4." and then some numbers and a date.

If you see that, R is installed and VS Code can talk to it. Move on.

If you see an error, or nothing happens at all, stop here. Either R is not installed or the R extension is not installed. Do not try to fix it by installing things at random. Write down exactly what the screen says and bring it to office hours or email it to me. A screenshot is perfect.

Step 2: Install the helper that fetches our course package

Our course package does not live in R’s usual store, so we need one small tool that knows how to fetch it from somewhere else. That tool is called remotes.

You only ever run this once, on this computer, for the whole semester.

install.packages("remotes")

What you should see: a lot of text scrolling past, some of it red, ending in something like package 'remotes' successfully unpacked.

Red text in R is not automatically an error. R writes ordinary progress messages in red. Only the last line matters. If R asks you a question in the console, for example whether to use a “personal library”, answer yes.

Step 3: Install the course package

Now we fetch the course package itself, v2v. It holds our datasets and the shortcuts we will use all term.

This one takes a few minutes the first time. Let it run. Go get water.

upgrade = "never" matters. Without it R offers to update dozens of other packages, and saying yes to that on Windows fails halfway: Windows will not overwrite a file that another program is holding open, so some packages roll back to the version you already had and the install dies on the one it needed.

remotes::install_github("AURA-Lab-SIUE/v2v-r", upgrade = "never")

One thing that confuses everyone, so read it once now: the thing we download is called v2v-r, and the thing we use is called v2v. Two names, same course package. That is normal for R and it is not a typo.

If R asks “Which would you like to update?” and offers a numbered list, type 3 for None and press Enter. If it asks about installing from source, answer no.

Step 4: Switch the package on

Installing a package puts it on your computer. It does not switch it on. library() switches it on, and you do this every time you start a new R session, not just once.

library(v2v)

What you should see: nothing, or a short startup message. In R, silence usually means success.

Step 5: The real check

This is the one that matters. setup() is a function we wrote for this course. It looks over your whole installation and prints a checklist: green checks for what is working, red marks for what is missing.

setup()

What you should see: a list of package names with green check marks, a VS Code section, then a Command-line tools section. The VS Code section lists languageserver and httpgd, which the R extension uses; a yellow mark there does not fail the check, and the install line under What to do next adds them.

Two red marks are expected and fine at this stage if you have not done the later setup steps yet: Quarto CLI and Git. Everything under Required R packages should be green. If a required package is red, setup() prints the exact command to fix it: copy that command, paste it into the console, press Enter, then run setup() again.

Step 6: Prove it can actually get data

Last one. This pulls five rows of real Twitch chat out of the course dataset, so you can see that the package is not just installed but working.

twitch_chat(n = 5)

What you should see: a small table, five rows, with columns of usernames and message text.
